# 需求说明

## 背景

EasyCut 桌面版（Tauri 应用）的开发周期长，而用户当前最急需的是**真正能跑起来的视频处理能力**：把网盘里的长视频整理成切片库，再用切片批量混剪出去做去重分发。PyCut 是为此建的云端执行管线，跑在 Arlo 的云电脑上，纯命令行。

## 目标

1. 功能一：把长视频批量整理成标准化、分类归档的切片库。
2. 功能二：用切片库批量混剪成片，成片之间做好去重（画面/音频/结构多层差异），可直接分发。

## 功能需求

### 功能一：整理切片

- 输入：用户提供的网盘长视频目录分享地址（可多个）。
- Arlo 扫描每个目录，与用户逐个确认目录作用后才开工。
- 分批下载（约 1G/批），按 MD5 去重，已处理的不重复下载。
- **时长 <10 秒的视频不切片**，直接跳过记账。
- 切点规则：场景边界优先、整段保留优先、尾段重分配（9 秒切 5+4 而非 8+1 丢 1 秒）、不机械等分、不拼不连续画面。
- 标准化输出：9:16、1080×1920、CFR 30、H.264 yuv420p SDR BT.709；不加字幕/音乐/贴纸/转场，不改原声。
- 按分类（结果证明 / 人物口播 / 使用过程 / 使用场景 / 商品特写 / 待复核）上传到网盘 `切片库/`。
- 每批更新网盘台账 `EasyCut-处理进度.md`（路径 + MD5 + 切片数 + 状态）。

### 功能二：混剪成片

- 输入：网盘 `切片库/` + 话术文件（UTF-8，每行一条独立话术）+ 用户的混剪指令（切片来源、话术、成片数、规格、去重强度）。
- **话术来源**（用户 2026-10-01 确认）：优先从爆款视频音频转录生成（`pycut transcribe` 抽字幕帧 → Arlo 读帧整理 → `product.check_script()` 事实核对）；或用户直接提供文案。
- **产品信息表**：`product.yaml`（仓库一份、网盘一份）是话术的唯一事实来源。用户通过改此表告诉 Arlo 产品核心特点（当前：灭鼠颗粒/红色/19元11包/安全灭鼠/对牲畜友好/安全低毒/慢性中毒死亡）。话术不得虚构表外信息。
- **开头策略**（用户 2026-10-01 确认）：爆款视频的开头都是同款，用同样的前几秒做开头更容易爆。混剪统一用爆款同款开头（开头池 `pycut hooks` 提取），只做轻微去重变换（裁剪位移/色调二选一），不做镜像/变速等损伤钩子效果的变换。
- N 条成片一次整体规划：固定 seed 可复现；同条内不重复高重叠 source range；素材不足如实报错。
- 声音：用户音频原样使用，或 TTS 按原文配音（多条建议轮换音色/语速做音频去重）；素材原声默认关闭。
- 去重强度三档（轻 / 中 / 强），默认中：镜头重排、裁剪位移、色调抖动、镜像、变速微调、字幕变化、片头片尾差异帧按档叠加。
- 成片上传到网盘 `成片/<批次>/`，台账记录。

## 非功能需求

- 纯命令行，无图形界面。
- 断点续跑：以网盘台账为唯一事实来源，中断后按台账恢复，不从头来。
- 幂等：同一 MD5 的源视频不重复处理；同一批次不重复渲染已成功的成片。
- 磁盘预算：本地只留当批物料（约 1G），处理完即删，不长期存视频。

## 约束

- 不删除、不移动、不改名用户的源视频文件。
- 不把 `切片库/` 的输出重新当作源视频处理。
- Arlo"看"视频的方式为抽帧 + 元数据 + 场景检测，语义判断精度有限，关键分类接受用户抽查纠正。

## 范围外

- 桌面 GUI（那是 easycut 仓库的事）。
- 激活码真实验证、在线更新等桌面版功能。
- 第三方平台审核规则的对抗性研究（只做常规去重变换）。
